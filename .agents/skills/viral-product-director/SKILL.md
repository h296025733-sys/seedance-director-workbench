# 爆款产品洞察导演

把“参考片看起来很火”转化为有证据边界的产品洞察、原创说服链和可执行视频方案。保留心理机制、注意力机制、痛点、证明与转化逻辑；不默认复制原片动作、台词、人物、镜头或独特表达。

## 启动与路由

1. 读取工作区 `AGENTS.md`、成功/失败经验、品牌/产品/镜头/禁用规则。未确认的长期偏好继续标记 `待确认`。
2. 判断任务：
   - `REFERENCE`：只分析参考片，或从其机制重新创作。
   - `ORIGINAL`：没有参考片，从产品、受众和目标原创。
   - `HYBRID`：保留经证据支持的结构功能，重写表达并接入用户产品。
3. 有参考视频但没有证据包时，先用 `watch-video`；再用 `viral-video-breakdown` 获取事实时间轴。不得凭印象声称“为什么爆”。
4. 用户要求动作、镜头和时序原样保留时，路由到 `replicate-viral-video`，不要继续本 Skill 的原创流程。
5. 混合任务由本 Skill 负责策略、痛点、产品承接、人物功能和原创脚本；只有选定的局部高保真动作/镜头交给 `replicate-viral-video`；生成执行层交给 `seedance-director` 与 `seedance-ui-planner`。

## 核心工作流

### 1. 盘点输入与主动取证

检查用户提供的视频、图片、网页、文件和当前工作区证据；能从已有材料确认的内容不重复询问。记录产品、规格、价格、平台、时长、目标受众、购买阶段、主目标、人物、品牌、禁用表达、可用模型和生成次数。只有缺失项会实质改变策略时才问最少量问题。

### 2. 建立事实边界

对参考内容使用：

- `FACT`：直接可见、可听、可测或可追溯的内容；绑定时间戳和证据路径。
- `INFERENCE`：由多项事实支持的心理或传播机制推断；写出证据链和替代解释。
- `UNKNOWN`：视频本身不能证明的投流、账号权重、定向、完播、点击、转化、销量或爆款因果。

对产品建立逐项宣称清单。缺来源的核心卖点标为 `待用户确认`，不得进入正式台词、字幕或视觉证明。若用户明确把无证据宣称设为必讲核心，不得擅自换成另一主张后继续输出正式脚本或直接粘贴提示词；先给宣称表和最小补证清单，最多提供标为“不可执行、待用户选择”的低风险方向，等待用户补证或明确同意改题。

### 3. 选定一个主痛点

明确目标用户看到视频前的状态、购买阶段、功能痛点、情绪痛点、身份/社交痛点、害怕失去的东西、希望立刻获得的结果，以及主要顾虑和反对理由。短视频默认只攻击一个主痛点；其余卖点只保留能支持该痛点的一项。

### 4. 诊断机制并做原创映射

覆盖 0–1 秒停止滑动刺激、0–3 秒钩子、好奇缺口与偿还、冲突/反差/意外、产品介入时点、证明类型、节奏与声音、信任、互动诱因和结尾回报。

逐项建立映射：

`参考片有效机制 → 触发心理 → 产品能否真实承接 → 适合的视觉证明 → 保留的结构功能 → 重新创作的表达 → 禁止复制的资产`

形成原创说服链：

`用户当前状态 → 唤醒并具体化痛点 → 旧方法为何失败 → 产品介入 → 可视化证明 → 结果 → 消除反对 → 情绪回报 → 行动建议`

产品必须在因果链中承担解决机制，不得在结尾突然作为装饰出现。

### 5. 先出三个差异化方向

进入详细分镜前，提出三个在叙事入口、证明方式或情绪路径上真正不同的方向。按统一量表评分，说明分数只是策划决策工具，不是市场表现预测。推荐一个主方案，并写清取舍与有限生成次数下的风险。

### 6. 设计人物、证明与执行

先定义人物的叙事职责，再决定人物形象。人物应服务于受众代入、产品逻辑和证明动作，不以“好看”代替功能。AI 人物必须原创、虚构、成年，不冒充真人公众人物，不复制现有角色；提供身份锚点和生成提示词，并在生成后检查一致性、手部、人数与可读性。

为核心卖点选择可被画面诚实承接的证明：现场演示、前后对比、细节特写、过程证据、数字证据、用户证言、专业解释或失败/成功对照。不能验证的证明不得伪造。

### 7. 完成交付与门禁

按 `script-and-shot-delivery.md` 产出完整策划。涉及 Seedance 时，先输出《Seedance官网执行卡》，再给导演完整版和直接粘贴版。执行参数只使用当前官方、平台、账号或用户界面证据；`UI_VISIBLE` 不等于可选或已生成验证。

生成前运行 `validation-gates.md` 的审核。未经用户明确授权，不登录、上传、消费积分或生成正式视频。

## 硬停止条件

出现以下任一项时，停止在本地审核/补证阶段，不让用户“先花一次钱试试”：

- 核心产品事实或宣称没有来源，或受监管结论尚未核验；此时不输出正式脚本、可直接粘贴提示词或付费执行卡。
- 不知道主要用户、购买阶段或唯一主痛点。
- “爆款原因”只有空泛形容词，没有事实和推断链。
- 产品只是装饰，或镜头不能展示真实证明。
- 人物与受众、场景或产品使用逻辑不匹配。
- 直接复制原片独特台词、角色、品牌、镜头组合或受保护表达。
- 人物图、产品图、场景图或分镜图有明显错误。
- 上传顺序与 `@` 编号不一致，或素材职责冲突。
- 当前平台入口、模型/模式可选性或素材审核状态不明确。
- 生成次数有限但本地审核仍未通过。

## A/B 测试纪律

每个对照只改变一个主要变量：钩子文案、第一镜构图、痛点强度、证明方式、人物类型或 CTA。固定其余变量并写测试假设、指标与判定窗口。没有真实发布数据时不得宣布哪个版本“更爆”。

## 真值与记录

明确区分源码阅读、静态验证、本地材料执行、Codex 新任务发现、用户账号上传、真实 Seedance 生成和真实发布数据。只报告实际完成的层级；不把策划评分当作转化预测，不把本地审核当作平台通过，不承诺爆款或生成成功。
