# 外部工具与 GitHub 项目评估规则

## 目的

遇到能力缺口时优先复用成熟方案，但任何外部项目必须先经过来源、真实性、安全、隐私、必要性和回滚评估。评估不等于安装授权。

## 搜索与采用顺序

1. 现有 FFmpeg、FFprobe、Python、Node.js、Codex 与工作区脚本。
2. 轻量、可审计的本地脚本。
3. 成熟且已在环境中的库。
4. 官方工具、官方 SDK、官方文档方案。
5. 项目级安装的成熟 Skill 或库。
6. 隔离审查和测试第三方项目。
7. 最后才开发复杂新工具。

可搜索：GitHub 开源项目、Codex/Agent Skill、官方 SDK、FFmpeg 扩展、Python/Node.js 库、本地 AI 模型、视频/音频/镜头/OCR 项目，以及 Seedance 工作流。发现候选项目后先筛选，不把未评估项目清单直接交给用户。

## GitHub 可信度核查清单

### 仓库与维护真实性

1. 创建时间、最近更新时间。
2. 提交历史是否真实连续，还是一次性上传。
3. Commit 是否主要是批量生成文件。
4. 维护者账号年龄及其他可信项目。
5. Contributor 数量与贡献分布。
6. Star、增长、Fork、Watcher 是否合理。
7. Issue/PR 是否真实、是否有人回复。
8. 是否有正式 Release 与校验信息。
9. 是否有清晰且兼容预期用途的 License。

### 文档与实现一致性

10. README 承诺是否存在于实际代码。
11. 文档参数、入口、输出与代码是否一致。
12. 是否存在混淆、隐藏或生成式填充代码。
13. 是否有足够测试、样例或可复现步骤。

### 安全、隐私与供应链

14. 是否下载未知二进制或执行 curl/wget/PowerShell 远程脚本。
15. 是否要求管理员权限、修改注册表、计划任务、后台服务。
16. 是否读取浏览器 Cookie、工作区外文件或敏感环境变量。
17. 是否收集遥测或向第三方发送文件。
18. API 权限是否合理，Key 如何读取、存储和记录。
19. 依赖来源、锁定方式、安装脚本和供应链风险。
20. 临时文件与删除逻辑是否限制在安全目录。

### 可测试与可回滚

21. 能否在项目隔离目录或临时环境中测试。
22. 是否支持 Windows、UTF-8、中文/空格/长路径。
23. 能否彻底卸载，哪些文件和配置需要回滚。
24. 是否存在更成熟、更轻量或无需安装的替代方案。

## 安装必要性

即使项目可信，也必须回答：

- 现有能力是否已经能可靠完成；
- 项目是否只是包装简单命令；
- 是否实质提高准确率或节省大量时间；
- 是否引入大型依赖、磁盘消耗或长期维护；
- 是否影响其他工作区、增加 API 费用或隐私风险；
- 是否可仅吸收必要知识/代码，而不完整安装。

## 评级

- **A**：成熟可信、维护活跃、有真实用户、代码清晰、风险低。
- **B**：总体可信，少量风险可通过版本锁定、隔离或配置控制。
- **C**：可能有用，但使用量少、维护不足或必须隔离验证。
- **D**：风险较高、收益不足或难以回滚；不建议安装。
- **E**：明显可疑、虚假宣传、文档与代码不符或存在重大安全风险。

默认只建议 A/B。C 只有在“无成熟替代、问题重要、可隔离、不接触敏感数据、可完整回滚”全部满足时才可请示。D/E 不得建议安装。

低使用量、低 Star、低 Fork、无 Issue 或无 Release 是风险信号，但不能单独证明项目虚假。

## 向用户请示的固定内容

1. 当前问题与现有能力不足。
2. 候选项目、固定 Commit、License 与评级。
3. 能解决什么、为什么值得、替代方案。
4. 安装/运行会改动什么，是否收费、是否需要 API Key。
5. 是否上传本地视频、音频或图片。
6. 风险控制、卸载与回滚。
7. 明确结论：推荐安装或不推荐安装。

未经明确同意，不得安装、运行安装脚本或第三方程序、运行远程脚本、添加全局依赖、修改系统环境。

## 记录要求

每个有价值候选项目都追加到 `knowledge/候选工具评估记录.md`，记录发现日期、问题、名称、仓库、Commit、评级、价值、风险、替代方案、是否请示、用户决定、是否安装、实际效果和是否保留。
