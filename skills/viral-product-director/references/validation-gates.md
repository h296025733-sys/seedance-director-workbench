# 验证门禁

进入详细分镜、生成图片、准备付费生成、验收成片或更新长期经验前完整读取。任何自动检查通过都不能代替原图/视频的人工视觉复核。

## G0 输入与证据

- [ ] 原始文件可读且保持只读，衍生物写入任务目录。
- [ ] 参考视频已有元数据、时间戳、关键帧/接触表、镜头和声音证据；缺失项已降低可信度。
- [ ] 产品名称、规格、价格、使用方式和核心卖点均有来源位置。
- [ ] 核心宣称通过证据门禁；待确认项未进入正式脚本。
- [ ] 受监管品类的当前法规和平台规则已用政府/监管/平台官方来源核验。
- [ ] 参考、人物、品牌和衍生素材的权利/授权边界已记录。

阻断：核心宣称无来源、参考不可读、权利边界不明或高风险规则未核验。若用户把无来源宣称指定为必讲核心，阻断期间不得通过自行换题来输出正式脚本、官网执行卡或直接粘贴提示词；必须先请求证据或取得用户对低风险改题的明确选择。

## G1 策略与原创性

- [ ] 明确 `REFERENCE / ORIGINAL / HYBRID` 和主要购买阶段。
- [ ] 只选一个主要痛点，产品能真实承接。
- [ ] 参考分析分开 `FACT / INFERENCE / UNKNOWN`，关键事实有时间戳/路径。
- [ ] 爆款机制有观察证据，不把投流、完播、转化或因果当作已知。
- [ ] 完成“机制→心理→产品承接→视觉证明→保留功能→重写表达→禁止复制”映射。
- [ ] 原片独特台词、人物、品牌、标志性镜头组合和受保护表达未被直接复制。
- [ ] 产品在说服链中实际解决问题，不是结尾装饰。

阻断：空泛“节奏快所以爆”、产品不能证明、痛点不清或方案实质是未授权套皮。

## G2 创意选择

- [ ] 三个方向在叙事入口、证明方式或情绪路径上真实不同。
- [ ] 12 项评分都有当前证据或明确假设依据。
- [ ] 评分声明为策划工具，不是市场预测。
- [ ] 推荐方案的产品中心度、视觉证明和合规安全性达到门槛。
- [ ] A/B 一次只改变一个主要变量。

阻断：三个方向只是改写文案，或推荐方向依赖未经证实卖点。

## G3 人物、产品与图片

- [ ] 人物的叙事职责、受众代入和证明功能明确。
- [ ] AI 人物为原创虚构成年人物，不冒充真人/公众人物或复制现有角色。
- [ ] 身份图的脸、发型、体型、服装和配色一致。
- [ ] 人物数量、手部、肢体、产品交互和画面可读性通过原图目视检查。
- [ ] 产品外观、比例、颜色、包装结构和 Logo 位置与证据一致。
- [ ] 场景图、动作图、产品图和分镜图职责单一；错误或冲突图片已拒绝。
- [ ] AI 图没有伪造实验、数据、证言、认证或产品效果。

阻断：人物漂移、手部/人数错误、产品变形、分镜不可读或素材职责冲突。

## G4 脚本与 Seedance 执行卡

- [ ] 0–1 秒刺激、0–3 秒钩子、好奇偿还、证明、反对消除、回报和 CTA 完整。
- [ ] 每镜只有可辨认的主要事件，时长与事件密度合理。
- [ ] 镜头表包含时间、画面、人物、动作、景别、机位、运镜、台词/字幕、音效、产品职责和心理作用。
- [ ] 官网参数来自当前证据，状态词未混用。
- [ ] 只上传实际使用素材，每项有核心职责和“不参考内容”。
- [ ] 实际上传顺序与所有 `@图片/@视频/@音频` 编号逐项一致。
- [ ] 导演完整版和直接粘贴版没有冲突镜头词、重复形容词或不可执行密度。
- [ ] 当前平台入口与素材审核状态明确。

阻断：参数靠记忆猜测、编号错位、入口未确认或有限次数方案仍有本地可发现错误。

## G5 付费前决策

- [ ] 用户明确授权本次上传与积分消费；授权范围、平台和次数明确。
- [ ] 首次验证最高风险片段，并有量化通过标准。
- [ ] 第二次只在第一次通过硬门槛后执行。
- [ ] 失败时的单层修正与回滚路径已写明。

未授权时停留在本地执行包，不自动登录、上传或生成。

## G6 生成后验收

逐镜检查并记录原始成片路径/哈希、平台、模型、模式、参数、上传顺序与提示词：

- 0–3 秒钩子是否清楚；
- 产品是否真实出现、外观稳定并完成证明动作；
- 人物身份、服装、人数、手部和交互是否正确；
- 镜头顺序、构图、动作、转场、音画节奏和尾帧是否符合执行包；
- 是否出现原人物、未授权品牌、遮罩、水印、错误文字或虚假证明；
- 核心反对理由和 CTA 是否可读；
- 哪些是通过、局部偏差和阻断失败。

生成成功只表示平台产出文件；必须通过逐镜检查才可称为该任务范围内通过。一次通过不证明跨模型、跨账号或重复生成稳定。

## G7 发布与 A/B

发布数据存在时记录平台、版本、发布时间、流量来源、样本窗口和指标定义；避免把同时变化的多个变量归因于单一机制。没有真实数据时只保留测试假设，不宣布“爆款”“高转化”或胜出版本。

## 验证层级报告

最终明确列出：

1. **源码阅读**：读了哪些规则与素材。
2. **静态验证**：结构、引用、编码、行数和提示词一致性。
3. **本地执行**：实际运行了哪些脚本/媒体处理及结果。
4. **Codex 发现/独立测试**：是否在新任务或隔离调用中真实触发。
5. **账号上传**：是否真实通过素材审核。
6. **Seedance 生成**：是否消费额度并检查成片。
7. **发布验证**：是否有真实指标与单变量测试。

未完成层级必须明确写“未测试”，不得用静态或自测结果代替。
