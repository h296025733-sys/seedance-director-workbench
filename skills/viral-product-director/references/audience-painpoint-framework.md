# 受众与痛点框架

需要决定目标用户、购买阶段、主痛点、欲望、恐惧或反对理由时完整读取。

## 受众不是人口标签

同时定义：

- **人**：年龄范围、生活/工作角色、消费能力；只保留与购买逻辑有关的属性。
- **时刻**：何时、何地、刚发生什么，为什么此刻会停留。
- **任务**：想完成什么实际任务或情绪任务。
- **旧方法**：当前怎么解决，为什么不满意。
- **购买阶段**：未意识、问题意识、方案意识、产品意识、临近购买或购后使用。
- **证据需求**：此阶段最需要看见什么才会继续相信。

缺少发布数据时，受众画像是策略假设，不写成真实平台定向或已验证人群。

## 痛点三层

| 层级 | 核心问题 | 例示写法 |
|---|---|---|
| 功能 | 什么事情难、慢、贵、不稳或麻烦 | “每次都要反复……” |
| 情绪 | 这件事让人感到焦虑、厌烦、尴尬或失控 | “最烦的不是……而是……” |
| 身份/社交 | 它影响怎样看自己或被别人看待 | “不想在……时显得……” |

每层都标注来源：用户材料、评论线索、参考视频事实、行业研究或导演推断。不要根据年龄、性别、地区做刻板推断。

## 单一主痛点选择

候选痛点按以下问题比较：

1. 是否高频或高损失？证据是什么？
2. 能否在 0–3 秒内被看懂？
3. 产品是否真正、具体地承接？
4. 能否用画面而不是空口宣称证明？
5. 是否符合当前购买阶段？
6. 是否会引入无法证明的功效或高合规风险？

选择一个主要痛点，用一句话写成：

`当[具体用户]在[具体时刻]想要[任务]时，因为[阻碍]承受[功能/情绪/身份损失]，现有方法又因[失败原因]不能解决。`

其余痛点只可作为辅助，不要在十几秒内并列攻击。

## 欲望、损失与反对理由

建立四栏：

| 用户想立刻得到 | 害怕继续失去 | 主要顾虑 | 需要的消除证据 |
|---|---|---|---|
|  |  |  |  |

常见反对理由包括价格、麻烦、学习成本、效果怀疑、适配性、耐用性、安全、审美、售后和“我已经有替代品”。只能选择与真实资料一致、能被镜头或可信信息回应的理由。

## 原创说服链

逐项完成且不跳步：

1. 目标用户当前状态。
2. 痛点被唤醒。
3. 痛点被具体化或升级。
4. 旧方法为何失败。
5. 产品以解决机制介入。
6. 可视化证明。
7. 用户获得的可核查结果。
8. 主要反对理由如何被消除。
9. 情绪或身份回报。
10. 与购买阶段匹配的行动建议。

任一步只有夸张词、没有事实或画面承接时，回到产品证据或创意方向修正。
