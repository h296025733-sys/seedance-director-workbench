# Seedance 视频导演工作台

**先把参考片看明白，再把动作、镜头、节奏和素材职责写成可执行的制作材料。**

“照这个拍”经常有几种含义：沿用动作顺序、只换人物、改变画风、借鉴开头，或者只是喜欢整体感觉。没有先确定这一点，后续提示词容易把不该改的运镜改掉，又把本来要替换的人物保留下来。

这个仓库把参考视频研究、严格复刻和产品创作组织成一套本地工作流。确定性脚本整理媒体和时间轴证据，Codex 技能负责拆解与方案，模板负责素材映射、分镜、官网执行卡和生成后复核。

它交付的是证据与制作执行包。实际生成需要使用者在相应模型平台完成，再逐镜检查输出。

## 从一个明确的任务开始

例如使用自己的参考片，保留动作、镜头、运镜和节奏，只更换人物与背景：

```text
参考片里的动作顺序和镜头长度保持一致。
人物换成我提供的角色，背景使用自己的场景素材。
先给出逐镜拆解，再整理分镜、素材上传顺序和提示词。
看不清的动作或缺失素材请明确标出来。
```

处理时先记录每一段能看到和听到的事实，再建立需要保留、替换和限制变化的内容。人物外观参考、动作参考与场景参考承担不同职责，不能把所有图片一股脑交给模型后期待它自行分辨。

## 两条主要工作路线

| 路线 | 输入重点 | 输出重点 |
| --- | --- | --- |
| 高保真复刻 / 结构迁移 | 参考片、需要保留的动作与镜头、替换主体 | 时间轴、逐镜约束、素材映射和执行包 |
| 产品视频创作 | 产品资料、受众、卖点、证明方式和参考方向 | 创意、脚本、分镜、证明设计与平台交付材料 |

复刻路线的约束是尽量保持指定结构；产品创作路线需要重新决定如何证明卖点。两者的评价方式和需要的证据不同，仓库分别提供技能与参考文件。

## 从参考片到执行包

```text
本地参考片
  → 媒体信息、镜头与关键帧
  → 可选本地转录和声音观察
  → 时间轴事实 / 推断 / 未知
  → 保留、替换与变化约束
  → 分镜和素材职责
  → 平台执行卡、上传次序和提示词
  → 实际生成后逐镜复核
```

关键帧说明某个时点的画面，连续动作需要结合相邻画面和原片观察；字幕说明文字，不自动说明动作已经发生。模板将这些证据与制作决定分开，方便复核时回到来源。

| 层 | 主要文件 | 职责 |

## 取证路径的设计

`watch_video.py` 默认使用本地素材，网络 URL 需要显式 `--allow-network` 和相应下载工具。FFmpeg / ffprobe 用于媒体探测，镜头检测可使用可用的 PySceneDetect / OpenCV 或 FFmpeg 路径。

取证模式包含 `FAST`、`BALANCED`、`DIRECTOR` 和 `HOOK_DENSE`，用于不同的采样与观察需求。高密度采样更有利于看短动作，也会产生更多需要阅读的文件；自动镜头检测结果仍可能需要人工合并或补充。

本地转录是可选功能，需要指定依赖与模型。当前脚本没有实现外部转录服务；不能因为参数列表中有相关开关，就宣称已经接入外部 ASR。

## 结构迁移怎样描述

执行包构建器支持四种策略：人物替换、镜头变化、风格变化和混合迁移。

| 策略 | 保留与修改的重点 |
| --- | --- |
| `character-swap` | 将主体替换要求与原动作 / 镜头结构放在一起 |
| `camera-variation` | 明确允许变化的镜头条件 |
| `style-variation` | 描述风格目标，同时保留对应结构依据 |
| `hybrid` | 对不同维度分别指定保留与变化 |

构建器输出迁移清单、提示词工作文件、官网执行卡与人工补全 / 验收材料。它依据证据生成结构，不会凭空完成缺失的画面观察；人工要补齐未知动作、角色细节和未确定的素材。

素材权利状态单独记录。知道文件在本机存在，与知道可以使用或修改该文件，是两个不同判断。

## 产品视频：把卖点转成可观察的证明

产品导演技能先整理产品资料与允许的声明，再确定受众问题、人物角色和证明方式。卖点如果只能写成一句形容词，就很难变成可信的镜头。

相关参考文件分别处理：

- 产品输入与声明范围。
- 受众痛点与内容机制。
- 角色、动作和证明设计。
- 创意评估与脚本 / 分镜交付。
- 平台执行材料与验证门槛。

这些文件约束的是制作过程。没有实验素材、产品证据或平台实际结果时，不能把创作建议写成已证明的效果。

## 最终交付材料

| 材料 | 让执行者能够确定什么 |
| --- | --- |
| 逐镜拆解 | 每段发生什么，时间范围和来源是什么 |
| 保留 / 替换清单 | 哪些动作、镜头、人物或环境可以变化 |
| 素材映射 | 每份图片 / 视频在生成中承担什么职责 |
| 上传次序 | 在平台中如何对应输入与提示词引用 |
| 官网执行卡 | 模式、任务要求和需人工补全内容 |
| 生成反馈 | 哪一镜偏离、需要怎样调整、下一轮改什么 |

参考时间轴与最终生成时间轴需要逐段比较。人物一致不代表运镜一致，时长一致也不代表动作时序一致，因此验收材料分别记录这些维度。

## 本地使用

建议 Python 3.11+，自行准备 FFmpeg / ffprobe。依赖按功能拆在 `tools/requirements/`，核心、姿态和审计路径分别安装需要的内容。

```powershell
python tools/doctor.py
python tools/validate_skills.py
python tools/watch_video.py --help
python tools/build_replication_package.py --help
```

使用自己的本地视频建立证据：

```powershell
python tools/watch_video.py --source "inputs/reference.mp4" --task-name "product-demo" --mode DIRECTOR
```

从实际生成的证据目录构建人物替换包：

```powershell
python tools/build_replication_package.py --evidence "本轮证据目录" --strategy character-swap --target-subject "自有角色参考" --rights-status confirmed
```

命令里的文件和目录需要替换；权利状态应按自己的实际依据填写。`doctor` 是环境诊断，`validate_skills` 是技能结构检查，不代表视频生成已经验收。

## 验证范围

2026-10-07 执行了 21 个 unittest 用例、相关脚本语法检查，以及中文路径和合成证据执行包检查。没有执行真实参考片完整取证、模型转录、平台生成与逐镜成片验收，见 [检查记录](docs/verification.md)。

执行包是可检查的制作输入，不是已经生成的成品，也不能保证任意模型都复现指定动作与镜头。最终判断应依据对应平台的实际输出。
